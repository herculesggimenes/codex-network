codex-network connects Codex chats and local ports across machines

Instead of treating each Codex session as local-only, codex-network gives every connected environment a shared way to reach conversations and localhost services elsewhere.

1

Conversation network

A chat can send a message or request to any other Codex conversation, even when that conversation lives on another laptop, VM, container, or RDE.

Connection A

Conversation chat-a1 asks another chat to continue work.

codex-network

Resolves the conversation id to the machine that owns it.

Connection B

Receives routed messages for chat-b1.

Connection C

Receives routed messages for chat-c1.

Example: codex-network send chat-c1 "continue from here"
2

Port forwarding network

A local service in one connection can be exposed to another connection with a stable name. Engineers avoid building SSH forwarding chains by hand.

Connection A

Runs a service at 127.0.0.1:3000.

codex-network

Creates named localhost forwarding between connections.

Connection B

Opens review-app at a local URL.

Connection C

Uses the same 127.0.0.1:49400 URL.

Example: codex-network http expose A:3000 --name review-app

Simple input

Users pass conversation ids, connection names, ports, and forward names.

Conversation path

Uses Codex app-server WebSocket JSON-RPC to resume, steer, or start turns.

Port path

Uses SSH localhost forwarding under the hood, managed by tmux.

Boundary

Private developer networking only. Shared ports bind to 127.0.0.1.
